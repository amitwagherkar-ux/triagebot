# Data Dictionary — CrelioHealth AI Triage Evaluator

This document defines the schema, types, sources, and business semantics for all entities in the evaluation platform.

---

## 1. Raw Jira Ticket Entity (`TicketSource`)

Represents raw Jira tickets sourced from `100ClassifiedPastTickets.csv` and `RawDataCurrentSprint.csv`.

| Field Name | Type | Nullable | Source File Column | Description |
| :--- | :--- | :---: | :--- | :--- |
| `ticket_id` | `String` | No | `JIRA ID` | Primary key identifier (e.g. `EA-14529`, `EN-13245`). Unique across each dataset. |
| `ticket_url` | `String` | No | `Ticket ID` | Full Atlassian Jira link (`https://crelio.atlassian.net/browse/{ID}`). |
| `summary` | `String` | No | `Jira Summary` | Title or problem statement written by the reporter. |
| `raw_classification` | `String` | No | `Classification` | Ground truth in Historical Baseline (`Bug`, `Config`, `Change Request`). In Current Sprint, acts as an unverified/provisional label. |
| `human_action_taken`| `String` | Yes | `Human Action Taken` | Remediation or triage outcome recorded in Jira (e.g. `Fixed`, `Working as expected`, `Enhancement`, `Fixed-DB Query`). |
| `last_comments_url` | `String` | Yes | `Last Comments` | Direct URL to the closing/investigation comment on Jira. |
| `verification_url` | `String` | Yes | `Verification Description` | Direct URL to QA verification comment. |
| `assignee` | `String` | Yes | `Assignee` | Assigned engineer or specialist. Empty for 14 sprint tickets. |
| `reporter` | `String` | Yes | `Reporter` | Individual who filed the ticket. |
| `priority` | `Integer` | No | `Priority` | Priority level (0 = Highest, 1 = Normal, 2 = Low). |
| `bot_action` | `String` | Yes | `Bot Action` | Jira column present in Current Sprint (all 52 rows currently blank). |

---

## 2. Model Run Entity (`ModelRun`)

Represents an evaluation run of a specific LLM model and prompt configuration.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `run_id` | `String` (PK) | Unique run identifier (e.g. `run_hist_v1`, `run_1728200000`). |
| `model_name` | `String` | Underlying LLM identifier (e.g. `Claude 3.5 Sonnet`, `Gemini 1.5 Pro`). |
| `prompt_version` | `String` | Prompt version tag (e.g. `v1.0 Baseline Zero-Shot`, `v2.0 Rule-Guided`). |
| `dataset_target` | `Enum` | Target dataset: `'HISTORICAL'` (100 tickets) or `'CURRENT_SPRINT'` (52 tickets). |
| `created_at` | `ISO 8601` | Timestamp when the model run was executed or imported. |
| `description` | `String` | Free-text operational notes regarding temperature, system prompt, or changes. |
| `results` | `Array<AIResult>`| List of AI prediction records for tickets in the run. |

---

## 3. AI Result Entity (`AIResult`)

The raw, immutable prediction output generated by the AI model for a given ticket.

| Field Name | Type | Allowed Values | Description |
| :--- | :--- | :--- | :--- |
| `ticket_id` | `String` (FK) | Matches `TicketSource.ticket_id` | Foreign key referencing the Jira ticket. |
| `classification` | `Enum` | `Bug`, `Config`, `Change Request`, `Needs Manual Triage` | The category predicted by the model. |
| `confidence` | `Float` | `0.00` to `1.00` | Normalized confidence score (e.g. `0.92` represents 92%). |
| `reason` | `Text` | Free-text | Natural language rationale explaining the classification. |
| `evidence` | `Text` | Bullet points / lines | Specific observable signals and symptoms extracted from the ticket. |
| `recommended_action`| `Text` | Free-text | Smallest practical next action suggested by the bot. |
| `suggested_owner` | `String` | Team / Name | Team or owner recommended for assignment. |
| `human_review` | `Enum` | `Required`, `Not Required` | AI recommendation on whether human inspection is required. |

---

## 4. Reviewer Evaluation Entity (`ReviewerEvaluation`)

Stores the human Product Analyst's validation decision, overrides, and feedback without mutating the original AI prediction.

| Field Name | Type | Allowed Values | Description |
| :--- | :--- | :--- | :--- |
| `ticket_id` | `String` (FK) | Matches `TicketSource.ticket_id` | Target ticket. |
| `run_id` | `String` (FK) | Matches `ModelRun.run_id` | Target model run evaluated. |
| `reviewer_decision` | `Enum` | `Correct`, `Incorrect`, `Needs Manual Triage` | Product Analyst's verdict on the AI prediction. |
| `reviewer_classification` | `Enum` | `Bug`, `Config`, `Change Request`, `Needs Manual Triage` | The authoritative ground truth class established by the analyst. Overrides initial labels. |
| `feedback_type` | `Enum` | *14 Taxonomy categories (see below)* | Root cause classification of model failure. |
| `reviewer_comment` | `Text` | Free-text | Rationale explaining why the classification was accepted or overridden. |
| `reason_quality` | `Enum` | `Good`, `Needs Improvement`, `Incorrect` | Evaluates AI reasoning quality independent of classification. |
| `evidence_quality` | `Enum` | `Good`, `Needs Improvement`, `Incorrect` | Evaluates whether cited evidence was factually grounded vs unverified inference. |
| `action_quality` | `Enum` | `Good`, `Needs Improvement`, `Incorrect` | Evaluates appropriateness of recommended next step. |
| `suggested_owner_quality` | `Enum`| `Good`, `Needs Improvement`, `Incorrect` | Evaluates team assignment suggestion. |
| `reviewed_by` | `String` | Name / Role | Analyst name or identity. |
| `reviewed_at` | `ISO 8601` | Timestamp | Time when review was logged. |

---

## 5. Feedback Taxonomy (14 Error Types)

1. `Wrong classification`: General classification mistake not covered by specialized categories.
2. `Insufficient evidence`: Bot guessed without sufficient context in the ticket.
3. `Expected behavior misunderstood`: Bot misinterpreted how the product is specified to operate.
4. `Actual behavior misunderstood`: Bot misread the reported error symptoms.
5. `Configuration mistaken for Bug`: Working feature setup or permission misidentified as code defect.
6. `Change Request mistaken for Bug`: Requested new feature or UI enhancement misidentified as defect.
7. `Change Request mistaken for Config`: Missing capability mistaken for an existing setting.
8. `Bug mistaken for Config`: Genuine software defect mistaken for configuration error.
9. `Unsupported assumption`: Bot hallucinated or inferred facts not present in Jira.
10. `Reason incorrect`: Reasoning was flawed or contradictory.
11. `Evidence incorrect`: Cited evidence was invalid or misinterpreted.
12. `Recommended action incorrect`: Bot advised incorrect first action.
13. `Suggested owner incorrect`: Bot assigned wrong team.
14. `Other`: Edge cases not covered above.
